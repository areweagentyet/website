# Are We Agent Yet? — approved design

## Purpose
Help developers find the available building blocks for general agent applications, judge evidence of readiness, compare alternatives and understand documented limitations. Later audience views may support production adoption and ecosystem research.

## Information architecture
- `/`: task-first field guide and interactive catalog. Seven tasks: choose models, connect tools/data, manage memory, run safely, orchestrate long-running work, evaluate/observe, deploy/serve.
- `/stack/`: full interactive stack with eight domains and all entries.
- `/solutions/[slug]/`: static solution profiles, original source context, task mappings, sources and dated editorial assessments.
- `/compare/`: shareable comparison of up to three entries.
- `/methodology/`: inclusion, evidence rubric, dates, gaps and editing workflow.

## Data
Copy the landscape snapshot into `src/data/catalog.json`. Keep task mappings and curated assessments separate. Assess 12–16 developer-facing projects from live primary sources; all other entries explicitly unassessed. Do not infer adoption from stars or extrapolate deployment guarantees. Standards, drafts and models retain distinct types and require appropriate assessment criteria.

## Presentation
Warm off-white, dark ink, vermilion accent. Large readable brand, editorial serif display, simple sans body, monospaced labels. Cardless rows, dividers, annotated stack diagram, compact evidence panels. Responsive keyboard-accessible controls. No fake metrics, aggregate ecosystem readiness percentages or invented endorsements.

## Architecture
Astro static output with TypeScript, structured local JSON and native browser modules. Static HTML remains useful without JavaScript; interactive filtering/comparison is progressively enhanced. Query strings preserve filters and selected comparisons. Optional localStorage retains comparison selections across pages. No database or authentication.

## Quality
Data integrity and functional behavior tests; Astro typecheck and production build; browser checks for search, filters, stack navigation, detail links, comparison persistence/share URLs, browser back, empty states, mobile layout and keyboard focus. Document local launch and evidence upkeep. Future user submissions require reviewed proposed changes, not immediate publication.
